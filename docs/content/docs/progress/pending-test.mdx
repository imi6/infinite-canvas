# Pending Tests

The current release needs manual verification in these areas:

- 画布公网参考图：左上角菜单「添加图片链接」应接受原图文件直链，保留完整签名参数，并将图片添加到画布供连接视频节点使用。导入链接或生成接口返回公网图片后，即使预览已保存为本地 Blob，视频请求仍应提交原链接；保存、刷新、复制、保存到素材并重新插入、切换多图主图及删除主图后均应引用当前图片的源地址。裁切、放大或替换为本地文件后不得误用旧原图链接。本地上传、粘贴、base64 图片及历史上已丢失源地址的图片仍需另行提供有效公网链接，不应伪装成已支持云上传。
- 新版视频响应：创建应识别顶层或 `data` 中的 `id`、`task_id`、`request_id` 并保存完整 ID；查询应识别 `status` / `state` 及成功、失败别名，失败应展示 `fail_reason` / `error`，未知状态不得当作成功。成功后优先下载 `/content`，仅该接口返回 404 时回退查询结果的 `url`、`video.url`、`content.video_url`、`output.url` 或 `video_url`，保留全部签名参数，外部下载请求不得带本站 API Key；其他下载错误应保留原任务供继续查询，不能重建任务。

- 生图创作须知：进入生图工作台应显示与视频页共用布局的须知弹窗，文案针对图片保存、尺寸与隐私，不应包含视频云端暂存 30 天或所有媒体链接无需登录的承诺。未确认时手动生成、Agent 自动生成及单张结果重试均不得发起图片生成请求；「暂不使用」应返回首页并清理待执行的生图 Agent 命令。生图与视频应分别保存确认后 7 天免提示的截止时间，互不影响；仅勾选或取消不得保存，到期再次提示，两页顶部均可重新打开须知。

- 顶部工具区：普通页面和画布右上角不再显示文档外链图标，其余入口位置应自然收拢。
- 视频创作须知：进入视频创作台时应先显示须知确认弹窗，覆盖内容审核、浏览器本地记录与云端媒体暂存 30 天、重复引用不续期、模型规格、媒体链接无需登录、隐私与内容权利、避免重复提交，以及关闭或刷新页面可能影响任务结果回填的说明。未确认前，手动或 Agent 发起的新任务均不得提交 `POST /v1/videos`，但已有任务仍可继续查询；「暂不使用」应返回首页并清理待执行的 Agent 命令。只有勾选「7 天内不再提示」并确认后才保存 localStorage 截止时间，取消或单独勾选不得生效；到期后应再次提示，顶部「创作须知」仍可随时重开。弹窗桌面端前四项分两列、第五项通栏，手机端单列滚动，浅色和深色主题均应清晰可读。

- 本站公开目录同步：模型应来自 `https://sub.zzshu.cc/api/v1/model-plaza`，不再固定模型名称、数量或版本。启动时先读取 localforage 中最近成功的目录缓存，并自动刷新公开目录一次；目录按名称去重，优先采用明确的生图、视频能力，保留模型原始名称，不将嵌入和重排序模型当作文本模型。公开目录没有某类创作模型时不虚构该能力的默认项。配置页无需 Key 即可点击「同步本站目录」，应显示加载中、已同步数量、无目录或同步失败状态；请求失败或空目录不得清除最近成功的缓存与模型配置。
- 本站快捷配置与跟随：填写本站 API Key 或留空沿用已保存的 Key，点击「保存并启用」应保存 Key 并启用目录跟随；目录尚未获取时仍可保存，后续同步成功再填充模型。公开目录新增或下架的模型应在后续同步时更新；同名模型的脚本和手动能力覆盖继续保留，下架但有自定义脚本或能力覆盖的模型应转为手动保留，且不自动设为默认。其他渠道、自定义模型、历史节点和已有生成任务不受影响；公开目录不代表当前 Key 对全部模型均有权限，保存操作不验证 Key。
- 本站按 Key 查询：只有点击「按 Key 查询」才应通过 `/v1/models` 读取当前 Key 的实际可用模型，并显式切换为手动模型清单；后续启动和自动同步公开目录不得覆盖该清单，点击「同步本站目录」应重新启用目录跟随。查询失败或返回空列表时只提示错误，不修改任何配置。模型能力按目录、名称及已有手动配置识别，命名特殊的模型可在渠道编辑器校正；嵌入、重排序、转录和实时类模型不应自动成为创作默认项，原生音频默认仅选择 TTS/语音合成模型。请求期间修改的渠道名称及最新脚本应保留，Key 与模型配置仍保存在当前浏览器。
- 本站同步边界：旧目录缓存不得覆盖同步时间更新的渠道配置；自动同步过程中，已打开渠道编辑器的未保存草稿应保留。手动删选模型后应切为手动清单，调整能力或脚本则继续跟随目录。按 Key 查询期间若地址、协议或 Key 改变，应放弃旧请求结果。模型更名后，新请求应使用新名称，旧画布节点和远端任务仍保留原模型以便用户确认。

- 本站视频接口：OpenAI 格式提交 `POST /v1/videos` 应使用 JSON 和 Bearer 鉴权，字段为 `model`、`prompt`、数字 `duration`、`ratio` 和 `resolution`，自动比例提交 `adaptive`，实际参数须符合所选模型要求，不提交 multipart、`seconds`、`size`、`resolution_name`。HTTP 200 或 202 返回任务 ID 后应保存任务，每 30 秒查询状态，识别成功终态后请求 `/v1/videos/{id}/content`；明确失败才标记生成失败，约 5 分钟自动等待结束或查询中断后可继续查询原任务，不应重复提交。
- 视频参考素材：当前视频工作台入口可添加 30 张公网图片、10 段视频和 10 段音频，实际数量、时长、格式和组合以所选模型要求为准。1～2 张图片在首尾帧模式发送 `first_frame`、`last_frame`，多图或带音视频时使用 `reference_images`、`reference_videos`、`reference_audios`，两种模式不能同时发送。画布图片可保存在本地用于预览，但视频请求应使用保留的原始公网链接；只有本地文件、`blob:` 和 `data:` 的素材应明确提示先提供公网文件链接。有参考素材时允许提示词为空。新插入的 OpenAI 视频脚本模板也应提交同一 JSON 协议并解析顶层或 `data` 中的三种任务标识，立即返回任务 ID，由应用统一查询和下载；用户已保存的自定义脚本继续按其脚本执行。
- 视频创作台布局：桌面端采用宽表单与生成结果双栏，历史记录移至抽屉；生成模型应位于顶部，下方提供「文生视频」「首尾帧」「参考生视频」三个创作方式及对应说明。文生视频仅显示画面描述，首尾帧显示两个独立图片卡片，参考生视频将图片、视频和音频归入标签切换区域，不应继续堆叠全部素材空态；生成参数可展开，工作台不再重复展示旧模式控件。浅色、深色主题及窄屏下应保持清晰的间距与层次。
- 视频创作方式与素材：文生视频仅提交提示词；首尾帧要求首帧、尾帧可选，每个卡片以一条公网图片链接替换对应图片，只提交 `first_frame` 和可选 `last_frame`；参考生视频按 `reference_images`、`reference_videos`、`reference_audios` 提交，图片最多 30 张，视频和音频各最多 10 段。切换方式应保留各自草稿，但提交仅包含当前方式的素材，不得携带隐藏素材。生成记录需保存并恢复所选方式和素材，新建需清空草稿。
- 视频创作台音视频入口：参考生视频的对应标签下可每行添加一个公网文件直链，只添加链接不应先下载素材；素材可通过播放器预览并单独移除。音频数量、格式、时长和输出声音能力应提示由所选模型决定，不再展示全站通用时长承诺；有参考素材时允许提示词为空。查询中断后继续查询原任务，不重新提交素材或创建任务；入口不应暗示已支持本地上传至公网。

- 镜像发布：推送 `local/billing` 后应由 GitHub Actions 构建并推送 `ghcr.io/imi6/infinite-canvas:latest`，平台仅为 `linux/amd64`；镜像仓库只保留 `latest` 标签对应的版本，不生成版本号、提交号或额外架构镜像。默认 Docker Compose 应拉取此镜像，启动后的 API 地址选择应包含两个自定义地址。

- API 地址预设：首次使用及新建 OpenAI 渠道应默认使用 `https://sub.zzshu.cc`；编辑渠道时可以从下拉选项中选择 `https://sub.zzshu.cc` 或 `https://apisub.zzshu.cc`，也可以手动输入其他地址；保存并重新打开后应保留所选地址。

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
